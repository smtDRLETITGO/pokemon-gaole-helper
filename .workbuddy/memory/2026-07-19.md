## HP fallback — **v4 混合策略完成 ✅**
- **v3 fallback 問題**：二次 `ocr.predict()` 不可靠（"No available adapters" 警告），0 次成功
- **v4 解法**：改為「全圖先行（首 predict 可靠）→ 行級 ROI 主力 → 已緩存的全圖結果補漏」
  - 核心發現：PaddleOCR WASM 的第二次及之後的 predict 呼叫不可靠，但首次 predict 總是正常
  - Phase 1：`cropROI([0,0,1,1])` + `ocr.predict()` → fullItems 快取
  - Phase 2：4 行 ROI predict（主力，同 v3）
  - Phase 3：missing stats 從 fullItems 錨點提取（不觸發二次 predict）
- **v4 成果**：
  | 指標 | v3 | **v4** |
  |---|---|---|
  | 六維總準確率 | 92.1% (387/420) | **96.2% (404/420)** |
  | HP 準確率 | 74.3% (52/70) | **98.6% (69/70)** |
  | Perfect cards | 47 (64%) | **~60 (82%)** |
  | 完全失敗 | 0 | **0** |
  | 146 張耗時 | 50.8s | **97.8s**（多一次全圖 predict） |
  | HP null 張數 | 18 | **0**（僅 1 張錯誤值 + 2 speed null） |
  - v4_full_cache 成功補值 23 次 / 18 張卡（16 張 HP + 2 張多欄位）
  - 仍殘留：speed 2 null (056,058) + speed 合併需 split heuristic

### 教訓固化
- PaddleOCR WASM 二次 predict 失效 → 全圖先行快取模式是唯一可靠 fallback
- 此教訓已寫入 correction_memory.json globalRules pitfalls
